Google Drive → Odoo Sync & Verification

Mirror a Google Workspace Drive into Odoo, stage every spreadsheet tab, prove both sides agree with content hashes, and heal only what a human approves.

Read this before installing

A Google Cloud service account, used on its own, sees nothing. It is a separate principal with its own empty Drive corpus, so files.list returns an empty array with HTTP 200 and no error — which looks exactly like “everything was deleted”. This module therefore requires domain-wide delegation with subject impersonation. The full walkthrough is in README.md, and the built-in Test Connection wizard verifies each step independently.

What it does

  1. Discovers every file and folder visible to one impersonated Workspace identity — My Drive, shared-with-me items from colleagues and outside consumer accounts, and every shared drive.
  2. Classifies each object by MIME type: folder, native Sheet, native Doc/Slides/Drawing, binary blob, shortcut, or unsupported.
  3. Mirrors non-spreadsheet content into ir.attachment, preserving the folder hierarchy. Community-compatible: no dependency on Enterprise Documents.
  4. Stages every tab of every spreadsheet — native Google Sheets and uploaded .xlsx — as its own dataset with its own header schema.
  5. Promotes rows into real business models only where an administrator authored and enabled a declarative mapping. Never guessed, never automatic.
  6. Verifies with an order-insensitive, bucketed-Merkle content hash on both sides, drilling into rows only where the hashes disagree.
  7. Reports drift as first-class Odoo records plus a downloadable JSON and HTML artefact.
  8. Heals through an explicit, fingerprint-guarded plan — dry-run by default.

Design commitments

Commitment Why
Read-only Google scopes The module never obtains a write scope, so it is structurally incapable of damaging Drive. Not a policy — a property.
Identity is never a title Files are keyed by Drive file id, tabs by numeric sheetId, rows by ULID or a declared natural key. Two files may legitimately share a name.
A missing mapped column is a hard stop Treating an absent column as empty cells would write NULL over an entire Odoo column. Zero rows are staged instead.
Deletes carry a higher evidence bar Creates are asserted by data that is present; deletes are inferred from absence — and absence is what every read failure looks like. Seven independent guards must all pass, and even then the delete is soft.
Hard delete is unreachable No automated path can call unlink() on a business record, at any threshold, under any configuration.
Preview and apply share one code path If dry-run and apply were computed separately, the preview would be a plausible-looking lie.
Every cached hash is version-keyed Change a normalization rule and every stored hash is invalidated. Serving a stale hash as verified is a silent false pass — the worst failure a verification system can have.

Report-first by default

Promotion is opt-in per dataset and ships disabled. Auto-heal is opt-in per mapping and ships disabled. A deployment that never enables either is still a complete, useful product: it mirrors your Drive, stages every spreadsheet tab, and tells you every day whether Odoo and Drive still agree — without writing a single business record.

Requirements

  • Odoo 18.0, Community or Enterprise.
  • Python packages google-api-python-client, google-auth, google-auth-httplib2 (see the repository-root requirements.txt); openpyxl ships with Odoo.
  • A Google Workspace domain whose super administrator can authorise domain-wide delegation. Consumer @gmail.com accounts cannot be impersonation subjects — their shared files are reached through the Workspace user they shared with.
